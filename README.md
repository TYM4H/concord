# Concord

Локальное приложение для сопоставления сущностей. Ядро читает выбранные поля из двух источников, сохраняет пары и объяснения в JSONL. Результат открывается в браузере. Для файлового примера достаточно Python 3.10+ со стандартным модулем SQLite. Для реляционных источников используются отдельные драйверы.

## С чего начать

- **Посмотреть, как принимается решение.** Откройте иллюстрированный разбор последнего эксперимента. В нём есть реальные значения полей из синтетического набора, экраны Concord и сверка с заранее заданными правильными парами. HTML содержит все изображения. После клонирования откройте его в браузере, а на GitHub используйте **Download raw file**. [Разбор на миллионе записей](docs/pipeline/realistic-million.html) · [Результаты в JSON](docs/pipeline/realistic-million.json)
- **Попробовать приложение.** Запустите пример ниже. Для работы со своими базами перейдите в «Источники данных», сохраните два профиля, затем откройте «Новое сопоставление» и подберите поля. [Инструкция по подключению](#чтение-из-баз)
- **Присоединиться к разработке.** Начните с тестов, карты модулей и задач ближайшего этапа. [Границы модулей](#границы-модулей) · [План и критерии готовности](docs/roadmap.md) · [Эскизы интерфейса](docs/concepts.html)

## Подготовка рабочего места

Для команды подойдёт Python 3.13. Для клонирования приватного репозитория нужен доступ от владельца. Команды ниже рассчитаны на macOS и Linux.

```sh
git clone https://github.com/TYM4H/concord.git
cd concord
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-db.txt
.venv/bin/python -m unittest discover -s tests
```

Для разработки создайте ветку от свежей `main`, добавьте изменение и откройте pull request. В описании укажите, какой сценарий изменился и как его проверить. Изменения алгоритма удобно проверять ещё и на зафиксированной разметке. Локальные профили, пароли и выгрузки храните вне репозитория. Каталог `local-runs/` исключён из Git.

## Первый запуск

Из корня проекта выполните команды ниже. Пример содержит вымышленные записи.

```sh
mkdir -p local-runs/demo
python3 -m concord --rules examples/rules.json --left examples/left.jsonl --right examples/right.jsonl --output local-runs/demo/result.jsonl
python3 -m concord.viewer local-runs/demo/result.jsonl
```

Откройте [экран сопоставления](http://127.0.0.1:8765/). В примере совпавшее имя даёт 70 баллов. У пары Р-102 и 812 адреса почты различаются, поэтому при итоговом балле 70% она получает статус «Возможное совпадение». Откройте «Возможные совпадения» и нажмите «Сравнить», чтобы увидеть кандидатов и расхождения. Ссылка «Основания расчёта» открывает подробный расчёт для отдельной пары.

Просмотрщик слушает локальный адрес. Остановить его можно сочетанием Ctrl+C. Для другого порта добавьте к команде просмотра `--port 8766`. Для нового расчёта укажите новое имя выходного файла. Существующая выгрузка защищена от перезаписи.

## Рабочее пространство

Запустите приложение командой `.venv/bin/python -m concord.viewer --workspace local-runs` и откройте [Обзор](http://127.0.0.1:8765/overview). Можно начать с пустого каталога. Для файлового режима без драйверов подходит также `python3`. Команда с позиционным путём к JSONL по-прежнему открывает конкретный запуск.

- **Обзор** показывает сводку выбранного запуска, распределение результатов и число возможных совпадений без решения аналитика.
- **Сопоставление** открывает результаты, поиск по ID, фильтры сходства, сравнение, диагностику и выгрузку CSV. Через «Новое сопоставление» можно выбрать два источника и выполнить отдельный расчёт.
- **Источники данных** показывает поля и маршруты из результата и примеры из сохранённого снимка. Через «Подключить источник» можно ввести параметры PostgreSQL, MySQL или SQLite, посмотреть схему и ключи в режиме чтения, выбрать таблицу и поле ID. Кнопка сохранения помещает профиль без пароля в каталог `.concord-profiles` рабочего пространства.
- **Правила** показывает фактические параметры расчёта. Изменённые веса, пороги и режимы переносятся в форму нового запуска.
- **История запусков** собирает результаты JSONL в выбранном каталоге и на один уровень ниже. Дата в истории соответствует времени файла на диске. Ссылки на результаты привязаны к конкретному запуску, включая его ручные решения.

В мастере можно повторить расчёт по полям локального снимка, выбрать файлы JSONL или профили баз. Для двух профилей укажите идентификаторы и нажмите «Подобрать поля по двум профилям баз». Проверьте примеры, выберите нужные пары полей и запустите сопоставление. Пароли можно ввести в форме или передать в окружении процесса через `CONCORD_LEFT_PASSWORD` и `CONCORD_RIGHT_PASSWORD`. Для рабочего пространства с БД используйте окружение с драйверами из `requirements-db.txt`.

## Возможные совпадения, решения аналитика и CSV

В разделе «Сопоставление» возможные совпадения по умолчанию отсортированы по убыванию балла. Ссылка «Все оценённые пары по убыванию балла» открывает общий список с основаниями расчёта, включая сохранённые сравнения ниже нижнего порога кандидата.

Чтобы подобрать порог, нажмите «Настроить порог автосовпадения». Задайте новое значение и нажмите «Показать прогноз». Экран показывает число автоматических совпадений и ближайшие пары с обеих сторон границы. Флажок «Примеры без блокирующих расхождений» помогает найти пары, на которые влияет изменение порога. Для применения выберите «В мастер с порогом…» и запустите отдельную сверку. Порог для предпросмотра должен быть выше нижнего порога кандидата. Оба порога вместе можно изменить в разделе «Правила». Там же в столбце «При расхождении» выберите для каждого поля «Блокировать совпадение» или «Только 0 баллов». Нажмите «Применить к новому запуску», чтобы повторить расчёт с выбранными настройками.

На странице «Сравнение кандидатов» новый запуск показывает все оценённые пары для левого ID, включая варианты ниже нижнего порога кандидата. По девять вариантов помещаются на страницу, по три рядом. К этому сравнению можно перейти и из разбора записи без пары. В строках стоят поля выбранных правил, в столбцах — кандидаты справа. Видны исходные значения, результат нормализации, совпадения и расхождения. Для возможного совпадения доступны действия **Подтвердить**, **Отклонить** и **Отложить**. При необходимости впишите основание перед нажатием кнопки. Можно подтвердить несколько вариантов, изменить ранее принятое решение или открыть отложенные пары через фильтр «Отложено».

Каждое нажатие сохраняет текущий выбор, заметку и время в локальной базе. Например, рядом с `result.jsonl` появится `result.jsonl.review.sqlite3`. Закройте просмотрщик и снова выполните `python3 -m concord.viewer result.jsonl`, чтобы вернуться к сохранённым решениям. Для переноса или резервной копии завершите просмотрщик и скопируйте JSONL, базу ручных решений и диагностический снимок этого запуска, если он есть, в одну папку. JSONL хранит исходные результаты алгоритма. При открытии Concord сверяет его контрольную сумму с сохранённым запуском.

Кнопка «Скачать принятые пары · CSV» выгружает автоматические совпадения и подтверждённые аналитиком пары. В таблице есть исходные ID и их типы, пути к ID, автоматическая оценка и причина, фактические сравнения (`evidence_json`), заметка и время ручного решения. Колонка `acceptance_basis` различает `automatic` и `analyst_confirmed`. Если открываете CSV в табличном редакторе, при импорте задайте тип «Текст» для столбцов с ID, чтобы сохранить ведущие нули.

## Почему левая запись осталась без пары

Откройте «Без пары» → «Записи слева». Выберите строку или найдите её по точному левому ID и нажмите «Разобрать». Справа можно искать по ID или фрагменту значения любого выбранного признака. В списке доступны все записи правой стороны этого запуска, включая записи, для которых уже найдена другая пара.

После выбора правой записи Concord показывает исходные и нормализованные значения и отвечает на один из двух вопросов.

- **Почему пара не прошла отбор?** Видно, какие поля пусты или расходятся, какие общие значения слишком часты и какой лимит действовал. У такой пары нет балла за подробное сравнение.
- **Почему балла не хватило?** Показаны зарегистрированный в запуске балл именно выбранной пары, нижний порог кандидата, недостающие процентные пункты и вклад каждого поля.

Новые запуски сохраняют рядом с результатом файл `concord-diagnostics-<id>.sqlite3`. Идентификатор находится в `diagnostics.id` первой строки JSONL. Снимок содержит ID, исходные и нормализованные значения полей, частоты и баллы кандидатов ниже порога. В снимках версии 2 эти баллы сохранены для всех левых ID. В версии 1 журнал содержит только кандидатов для левых записей без пары. Его размер зависит от объёма этих данных. Разбор использует локальный снимок, в том числе после закрытия исходных баз.

У прежних запусков сохраняются исходная причина и, если пара оценивалась, ближайшее из сохранённых сравнений. Для поиска произвольной правой записи нужен запуск со снимком. Разбор не создаёт соответствие и не меняет выгрузку принятых пар.

## Чтение из баз

Установите зависимости для источников в окружение проекта.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-db.txt
```

Создайте JSON-профиль для каждой стороны. Для PostgreSQL он может выглядеть так.

```json
{"driver":"postgresql","host":"127.0.0.1","port":5432,"user":"analyst","database":"crm","schema":"registry","table":"person"}
```

Для MySQL укажите `"driver": "mysql"`, порт сервера и имя базы в полях `database` и `schema`. Для SQLite достаточно `{"driver":"sqlite","database":"source.db","schema":"main","table":"people"}`. Относительный путь к SQLite вычисляется от каталога профиля. Существующий файл открывается только на чтение.

Команда инспекции показывает колонки, их типы, первичные и внешние ключи. Если опустить `schema`, она выведет список схем. Поле `table` потребуется для сопоставления.

```sh
.venv/bin/python -m concord.sources left-source.json
.venv/bin/python -m concord --rules db-rules.json --left-source left-source.json --right-source right-source.json --output db-result.jsonl
.venv/bin/python -m concord.viewer db-result.jsonl
```

В правилах для полей основной таблицы укажите полное имя, например `registry.person.person_id`. Каждая сторона выбирает свой драйвер. Можно также сочетать БД на одной стороне и JSONL на другой. Результат включает настройки сопоставления и сведения о выбранных источниках. Пароли запрашиваются в терминале без отображения. Для неинтерактивного запуска поддерживаются `CONCORD_LEFT_PASSWORD`, `CONCORD_RIGHT_PASSWORD` и `CONCORD_SOURCE_PASSWORD` (инспекция).

### Предложения полей после выбора таблиц и ID

Укажите в двух профилях нужные схемы и таблицы, затем передайте имена колонок ID. Файл правил для этого шага не требуется.

```sh
.venv/bin/python -m concord.suggestions --left-source left-source.json --left-id person_id --right-source right-source.json --right-id employee_key
```

Concord выводит варианты в порядке пригодности к сравнению. Для каждой пары показаны пути, типы колонок, до трёх исходных примеров с каждой стороны, заполненность по ID и основания выбора. Примеры берутся независимо. Порядок их вывода не устанавливает связи между записями. Чтобы получить те же предложения для интерфейса или сохранить локальный отчёт, добавьте `--json`. Поля `left.via` и `right.via` перечисляют конкретные переходы, включая колонки составных ключей.

По умолчанию исследуются первые 100 различных ID в порядке сортировки в источнике и таблицы в пределах двух переходов по внешним ключам одной схемы. Параметр `--sample-size` принимает 1–500, `--max-hops` — 0–3. Нулевая глубина ограничивает поиск выбранной таблицей. Профилировщик обходит до 24 путей без циклов и до 128 полей, читает до восьми строк на выбранный ID **в среднем по пути**. Достижение предела строк помечает статистику пути как частичную. Значения длиннее 256 символов пропускаются. Статистика считается по разным ID, поэтому повтор одной связи не повышает частоту.

Подбор использует совместимость типов, части имён, характерный формат, пересечение нормализованных значений, заполненность и частоты. ID и колонки объявленных ключей исключаются из признаков. Совпадение только типа недостаточно. Константные поля, повторяющие одно значение у нескольких ID в выборке, исключаются. Возвращается до трёх вариантов справа для каждого поля слева. В JSON `rank` задаёт порядок предложений полей. Решение о совпадении записей принимается отдельно, при запуске с выбранными правилами.

### Подтверждение полей и запуск

Добавьте `--choose --draft selection.json` к команде подбора. Сначала Concord показывает пронумерованные предложения и примеры с обеих сторон. Введите номера нужных пар через запятую. Если одно поле получило несколько вариантов, выберите для него один. У каждой выбранной пары начальный вес 1.

```sh
.venv/bin/python -m concord.suggestions --left-source left-source.json --left-id person_id --right-source right-source.json --right-id employee_key --choose --draft selection.json
.venv/bin/python -m concord --selection selection.json --left-source left-source.json --right-source right-source.json --output reviewed-result.jsonl
.venv/bin/python -m concord.viewer reviewed-result.jsonl
```

Для отложенной проверки используйте только `--draft selection.json`. Все предложения в таком файле начнут с `"enabled": false`. Включите нужные строки, измените при необходимости `mode` (`text` или `exact`) и `weight` (больше 0 и до 100 включительно). При замене колонки укажите её путь в `left` или `right` и проверьте соответствующий `left_route` или `right_route`. Для прямой колонки таблицы маршрут равен `null`, для связанной он содержит фактические переходы и имя конечной колонки. Маршруты из предложений уже заполнены. Выполненный запуск сохраняет подтверждённые правила и использованные маршруты в заголовке выгрузки.

### Поля в связанных таблицах

В профиле можно задать маршрут от основной таблицы к признаку. Например, такой фрагмент `routes` описывает путь от человека через таблицу принадлежности к названию группы.

```json
{
  "routes": {
    "registry.person.membership.groups.label": {
      "via": [
        {"table":"membership","from":["person_id"],"to":["person_id"]},
        {"table":"groups","from":["group_id"],"to":["id"]}
      ],
      "column": "label"
    }
  }
}
```

Имя маршрута используется в правилах наравне с обычным полем. Каждый переход задаётся колонками предыдущей и следующей таблиц и проверяется по внешнему ключу. Допустимы прямые и обратные переходы внутри выбранной схемы и составные ключи. Разные ветки читаются отдельными запросами. Ядро объединяет значения по исходному ID, в том числе у записей, для которых связанные строки отсутствуют. Явное сравнение выбранного ID с другим ID и использование его копии по цепочке внешних ключей отклоняются.

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `concord/sources/adapters.py` | Реестр драйверов, создание подключения и открытие транзакции для чтения. Новый адаптер регистрируется здесь. |
| `concord/sources/reader.py`, `relations.py` | Инспекция схемы, проверка маршрутов и чтение выбранных колонок порциями. |
| `concord/suggestions/` | Выборка по ID, автоматический обзор путей по схеме, предложения полей и примеры. |
| `concord/rules.py`, `matching.py` | Нормализация, сравнение, индекс кандидатов и объяснение. Ядро принимает итераторы записей. |
| `concord/runs.py` | Запись настроек и результатов. Завершённая выгрузка публикуется одним действием. |
| `concord/viewer.py` | Локальный просмотр результата, фильтрация и постраничная выдача. |

Для добавления СУБД с диалектом SQLAlchemy требуется определить подключение, подтвердить режим чтения и проверить каталог, типы и потоковое чтение на сервере. Общие механизмы описаны в документации SQLAlchemy. [Инспекция схем](https://docs.sqlalchemy.org/en/20/core/reflection.html) · [Чтение порциями](https://docs.sqlalchemy.org/en/20/core/connections.html#streaming-with-a-fixed-buffer-via-yield-per)

## Вход и результат

Каждая строка входного JSONL — объект с ID (строка или целое число) и произвольно названными текстовыми полями. Ключи объекта соответствуют путям в настройках. Поле может содержать список значений, одиночное значение или null. Несколько строк с одним ID объединяются. Строковый ID сохраняет ведущие нули и отличается от числового. Идентификаторы служат только для адресации записей.

В [примере настроек](examples/rules.json) задаются независимые пути слева и справа, вес и режим каждого признака. Режим `text` применяет Unicode NFKC, сводит регистр и последовательности пробелов. Режим `exact` сравнивает исходные строки. Пустое значение даёт пропуск. В JSONL связанные данные передаются в виде полей проекции. При подключении базы Concord может получить их по маршрутам профиля.

В первой строке выгрузки хранятся версия формата и настройки. Далее идут записи с исходными ID, автоматическим статусом, основанием решения и результатами сравнений. Для непарной записи отсутствующая сторона имеет значение null. Если для записи слева проверялись кандидаты и все получили низкий балл, сохраняется подробный расчёт ближайшего из них.

## Как рассчитывается статус

1. Временная SQLite-база индексирует значения по признаку и считает число отдельных ID с каждым значением на обеих сторонах.
2. Для подробного сравнения достаточно одного общего нормализованного значения, которое встречается максимум у `block_limit` сущностей на каждой стороне (по умолчанию 64). Более частые значения учитываются при оценке уже отобранной пары. Пара без общего ключа пропускается, в том числе при опечатке в единственном признаке.
3. Для каждого признака выбирается самое редкое общее значение. Вклад равен весу признака, делённому на квадратный корень из большей из двух частот. Пропуск или расхождение дают нулевой вклад. Итог — сумма вкладов в процентах от суммы настроенных весов, округлённая до сотых.
4. По умолчанию нижний порог кандидата (`review`) равен 65, порог автосовпадения (`accept`) — 85. Обе границы включены. У каждого признака есть настройка `block_on_conflict`. По умолчанию блокировка включена. Если значения заполнены с обеих сторон и ни одно не совпало, такое поле блокирует автосовпадение. При `false` это поле даёт ноль баллов, а решение зависит от итогового балла и остальных полей. Пропуск значения сам по себе не блокирует совпадение. Несколько пар с одним ID допустимы.

Проценты показывают балл по заданным правилам. Параметры предстоит проверить на размеченных данных.

## Эксперимент с тёзками и опечатками

В PostgreSQL и MySQL прочитано по миллиону записей. Заранее заданы 850 000 правильных пар. При пороге 66,82 блокировка расходящейся почты дала 290 322 верных и 936 ложных автосовпадений. После снятия блокировки получилось 301 976 верных и 5 931 ложное. Этот эксперимент измеряет качество решения на синтетическом наборе. [Методика и подготовка тестовых баз](benchmarks/relational.md)

Для повторения подготовьте тестовые базы `concord_multi_01` и профили с правом чтения по инструкции выше, затем выполните команду из корня проекта.
