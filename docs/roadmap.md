# План развития Concord

План предлагает порядок работы для команды. Задачи сгруппированы по [этапам на GitHub](https://github.com/TYM4H/concord/milestones). Чтобы взять задачу, откройте её карточку, проверьте зависимости в разделе «С чего начать» и назначьте себя исполнителем. Отправная точка — [результаты размеченного миллиона](pipeline/realistic-million.json) и [разбор с экранами](pipeline/realistic-million.html). Порог автоматического совпадения в контрольном прогоне равен 66,82.

## Ближайший этап — понять и уменьшить пропуски

| Очерёдность | Задача и карточки GitHub | Что должно получиться |
| --- | --- | --- |
| 1 | Сравнение двух запусков на одном снимке. [#1 Расчёт переходов](https://github.com/TYM4H/concord/issues/1) · [#2 Экран и CSV](https://github.com/TYM4H/concord/issues/2) | Аналитик видит, какие пары перешли в другой статус, и открывает примеры по двум исходным ID. При наличии разметки отдельно видны правильные и ложные связи, потери на этапе отбора и потери по баллам. Без разметки показываются наблюдаемые переходы статусов. |
| 2 | Варианты сравнения полей. [#3 Опечатки в email](https://github.com/TYM4H/concord/issues/3) · [#4 Сходство ФИО](https://github.com/TYM4H/concord/issues/4) | Различать точное совпадение, близкое написание, пропуск и явное противоречие. Начать с перестановки соседних букв в домене. Для каждой пары видны исходные значения, применённое правило и его вклад. Прежний режим точного сравнения остаётся доступным для воспроизведения запусков. |
| 3 | [#5 Отбор кандидатов по частям ФИО](https://github.com/TYM4H/concord/issues/5) | Если текущий отбор пропустил пару, попробовать ограниченный поиск по частям ФИО. Ядро сохраняет причину включения кандидата и объединяет результаты точного поиска и поиска по частям ФИО. Проверить отдельно разные записи с одинаковым полным именем. |

**Почему такой порядок.** На контрольной разметке 9 301 правильная пара не дошла до оценки, ещё 462 175 набрали меньше 65. Снятие блокировки почты добавило 4 995 ложных связей. Экран сравнения нужен, чтобы отдельно измерять, какую проблему исправляет каждое изменение и сколько ошибок оно создаёт.

**Проверка этапа.** [#6 Контрольный прогон на миллионе](https://github.com/TYM4H/concord/issues/6). Прогнать обе версии на одной зафиксированной разметке. Приложить число пропущенных кандидатов, число верных и ложных автосовпадений, общее число оценённых пар, время и пиковую память. Для примеров «Русаков-Петухов», «Максимов» и «Лебедев» показать путь от кандидата до статуса. Целевой компромисс между полнотой, точностью и временем выбрать по результатам.

## Следующий этап — подключать реальные схемы

- **Связи без внешнего ключа.** [#7 Профиль и чтение](https://github.com/TYM4H/concord/issues/7) · [#8 Редактор и предпросмотр](https://github.com/TYM4H/concord/issues/8). В «Источниках» аналитик выбирает две таблицы и пары колонок, открывает предварительный просмотр и сохраняет связь в локальном профиле. Критерий готовности — подтянуть почту и несколько телефонов через такую связь, показать путь в карточке и повторить запуск после перезапуска приложения.
- **Несколько ролей одной таблицы.** [#9 Пути покупателя и продавца](https://github.com/TYM4H/concord/issues/9). Явно подписывать, например, контакт покупателя и контакт продавца. До запуска показывать образцы значений и число записей без контакта для каждого пути. Проверить, что сохранение одного пути не меняет другой.
- **Новые источники.** [#10 Выбор СУБД](https://github.com/TYM4H/concord/issues/10) · [#11 Реализация адаптера](https://github.com/TYM4H/concord/issues/11). Выбирать следующий драйвер по базам команды. Для каждого адаптера проверять чтение схемы, составные ключи, типы ID, постраничное чтение и запуск в паре с уже поддерживаемой СУБД. Сценарий подключения должен работать из интерфейса.

## Дальнейший этап — устойчивые большие запуски

- [#12 Ход запуска](https://github.com/TYM4H/concord/issues/12) · [#13 Место на диске](https://github.com/TYM4H/concord/issues/13). Показывать этап, число прочитанных записей, оценённых пар и объём локальных файлов. Перед созданием индекса оценивать место на диске. Проверить поведение при заполнении диска и повторном открытии последнего завершённого запуска.
- [#14 Отмена запуска](https://github.com/TYM4H/concord/issues/14). Добавить отмену длительного запуска. Завершённые результаты и решения аналитика должны открываться после отмены следующего расчёта. Возобновление имеет смысл проектировать после определения границ безопасной контрольной точки.
- [#15 Отчёт по наборам и группам ошибок](https://github.com/TYM4H/concord/issues/15). Сравнивать версии правил на разных размеченных наборах. Выделять группы с пропусками, распространёнными ФИО и дублями; сохранять версию данных и настройки рядом с результатами.

## Что спроектировать в интерфейсе

[Два черновых экрана](concepts.html) показывают, как аналитик мог бы сравнить запуски и проверить связь без внешнего ключа. Для первого экрана используются измеренные цифры эксперимента, для второго — демонстрационные значения. Это предложения к обсуждению и прототипированию в стиле текущего интерфейса.

Перед реализацией экрана сравнения согласовать, какой набор пар выгружается из каждого фильтра. Для редактора связей проверить три состояния на прототипе — пустая выборка, один контакт и несколько контактов у одного ID.
