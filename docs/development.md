# Руководство разработчика

Команды установки, тестов и экспериментов выполняются из корня проекта. Текущие приоритеты команды и критерии готовности собраны в [дорожной карте](roadmap.md).

## Подготовка рабочего места

Для команды подойдёт Python 3.13. Для клонирования приватного репозитория нужен доступ от владельца. Команды ниже рассчитаны на macOS и Linux.

```sh
git clone https://github.com/TYM4H/concord.git
cd concord
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-db.txt
.venv/bin/python -m unittest discover -s tests
```

Для разработки создайте ветку от свежей `main`, добавьте изменение и откройте pull request. В описании укажите, какой сценарий изменился и как его проверить. Изменения алгоритма удобно проверять ещё и на зафиксированной разметке. Локальные профили, пароли и выгрузки храните вне репозитория. Каталог `local-runs/` исключён из Git.

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `concord/sources/adapters.py` | Реестр драйверов, создание подключения и открытие транзакции для чтения. Новый адаптер регистрируется здесь. |
| `concord/sources/reader.py`, `relations.py` | Инспекция схемы, проверка маршрутов и чтение выбранных колонок порциями. |
| `concord/suggestions/` | Выборка по ID, автоматический обзор путей по схеме, предложения полей и примеры. |
| `concord/rules.py`, `matching.py` | Нормализация, сравнение, индекс кандидатов и объяснение. Ядро принимает итераторы записей. |
| `concord/runs.py` | Запись настроек и результатов. Завершённая выгрузка публикуется одним действием. |
| `concord/viewer.py` | Локальный просмотр результата, фильтрация и постраничная выдача. |

Для добавления СУБД с диалектом SQLAlchemy требуется определить подключение, подтвердить режим чтения и проверить каталог, типы и потоковое чтение на сервере. Общие механизмы описаны в документации SQLAlchemy. [Инспекция схем](https://docs.sqlalchemy.org/en/20/core/reflection.html) · [Чтение порциями](https://docs.sqlalchemy.org/en/20/core/connections.html#streaming-with-a-fixed-buffer-via-yield-per)

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m benchmarks.matching --rows 1000000
```

Сквозные проверки выполнены на PostgreSQL 14.17, MySQL 8.0.41 и SQLite. Для PostgreSQL → MySQL с миллионом людей с каждой стороны проверены выбор ID, подбор полей через внешний ключ, ручное подтверждение и содержимое каждой строки выгрузки. От отправки формы до получения первой страницы результатов прошло 54,21 с. Выгрузка 250 001 связи заняла ещё 4,30 с. У каждой записи в этом тесте не более одного кандидата. [Замеры до и после оптимизации, разметка и повторение прогона](../benchmarks/relational.md).

В отдельном прогоне ядра на этой машине 1 000 000 записей с каждой стороны дали 1 000 000 ожидаемых пар за 26,90 с. В этой синтетике у каждой пары есть уникальный общий код, а второй признак один на весь набор. Измерение включает построение временного индекса и формирование объяснений.

## Эксперимент с тёзками и опечатками

В PostgreSQL и MySQL прочитано по миллиону записей. Заранее заданы 850 000 правильных пар. При пороге 66,82 блокировка расходящейся почты дала 290 322 верных и 936 ложных автосовпадений. После снятия блокировки получилось 301 976 верных и 5 931 ложное. Этот эксперимент измеряет качество решения на синтетическом наборе. [Методика и подготовка тестовых баз](../benchmarks/relational.md)

Для повторения подготовьте тестовые базы `concord_multi_01` и профили с правом чтения по методике эксперимента, затем выполните команду из корня проекта.

```sh
.venv/bin/python -m benchmarks.realistic_email local-runs/realistic-repeat /path/to/postgresql.json /path/to/mysql.json
```

## Этапы разработки

| Этап | Результат |
| --- | --- |
| 1. Ядро и просмотр | Реализованы локальный запуск, выгрузка, фильтры по статусу, страницы по 20 строк и детали решения. |
| 2. Источники данных | Реализована серверная часть для PostgreSQL, MySQL и SQLite, включая многозвенные связи. Доступны проверка подключения из браузера, инспекция схемы и просмотр выборки запуска. |
| 3. Настройка и запуск из интерфейса | Мастер в браузере позволяет подобрать поля, выбрать режимы и веса и запустить расчёт. Командный интерфейс также поддерживается. |
| 4. Разбор и проверка масштаба | Ручные решения сохраняются локально. Доступны сравнение вариантов, возврат к сохранённым решениям и CSV принятых пар. История объединяет локальные запуски. Сквозной сценарий измерен на миллионе записей в каждой из двух СУБД. |

Пять исходных скриншотов хранятся в [макетах интерфейса](screens/). Экран результата следует композиции макета «Сопоставление». Для объяснений добавлена отдельная страница, поскольку такого состояния среди скриншотов нет. В боковом меню доступны все пять разделов.
