Concord — от двух баз до связей в CSV

У клиента может быть один ID в реестре и другой в клиентской базе. Concord помогает найти записи одного человека и сохранить оба номера. В этом отчёте показан путь одной такой связи — от просмотра исходных данных до строки в выгрузке.

1. Подготовка двух источников

Для запуска использовали две тестовые базы по миллиону записей. В PostgreSQL исходные ID взяли из таблицы registry.people, в MySQL — из customers. Набор синтетический, с полными тёзками и несколькими записями на одного человека. Правильные пары ID были известны заранее и использовались для проверки результата.

В разделе «Источники данных» можно выбрать каждую сторону и посмотреть исходные значения. Для этого запуска выбрали два поля — ФИО и электронный адрес. У каждой базы сохранилась собственная система ID.

2. Результат запуска

Concord автоматически принял 291 258 пар. Когда их сверили с заранее подготовленной разметкой, подтвердились 290 322 пар — 99,68 % от автоматически принятых.

3. Одна найденная связь

Записи 0000002 из PostgreSQL соответствует ID 1572540 из MySQL. Слева имя записано как «Баранов Георгий Олегович», справа — «БАРАНОВ ГЕОРГИЙ ОЛЕГОВИЧ». Электронный адрес в обеих записях один и тот же. Concord связал их автоматически, и эталонная разметка подтвердила, что это один человек.

4. Что получает аналитик

Кнопка «Скачать принятые пары · CSV» на странице результата выгружает все 291 258 принятых связей. Ниже — четыре столбца из строки Баранова. По этим ID можно соединить данные реестра и клиентской базы, а значение automatic указывает, как связь появилась в выгрузке.

Что уже умеет Concord

  • Локально сопоставлять записи из разных СУБД, работая с источниками в режиме чтения.
  • Показывать несколько кандидатов рядом, когда у человека есть дубли. Каждая связь сохраняет оба исходных ID.
  • Сохранять результаты запуска. К найденным парам можно вернуться через историю и повторно выгрузить их в CSV.

Что хотим сделать дальше

Расширить поиск по вариантам написания имён и добавить экран сравнения запусков, чтобы видеть, какие связи появились при изменении настроек. Для баз со сложной структурой планируем дать аналитику возможность самому указать, как основная таблица связана с контактами.
