Concord — сопоставление записей в двух базах

У одного человека могут быть разные ID в разных системах. Concord сравнивает значения полей и выгружает связи между исходными ID. Ниже — пример из сохранённого запуска на тестовых PostgreSQL и MySQL с миллионом записей с каждой стороны.

Подключение и выбор полей

В PostgreSQL выбрали таблицу registry.people и ключ person_id, в MySQL — customers и customer_id.

Concord предложил сравнить ФИО и почту и показал примеры с обеих сторон. В PostgreSQL почта лежит отдельно — приложение нашло её в таблице контактов по внешнему ключу.

Как одна пара попала в CSV

У записи 0000036 слева имя записано как «Сидоров 000008», у 1000036 справа — «СИДОРОВ 000008». После приведения к нижнему регистру значения совпали и дали 70 баллов. Одинаковая почта d000008@sample.test добавила ещё 30. Итог — 100 при пороге 85. Concord принял пару автоматически.

Фрагмент сохранённой выгрузки, четыре столбца из полной строки:

left_id,right_id,score,acceptance_basis
0000036,1000036,100.0,automatic

Сильные стороны проекта

  • Две разные СУБД можно сопоставить локально, в том числе когда нужное поле лежит в связанной таблице.
  • Для каждой пары видны исходные значения и вклад каждого поля. По выгрузке можно восстановить основание совпадения.
  • Одна запись может иметь несколько кандидатов. В текущей версии общее ФИО участвует в отборе при любой частоте, а его распространённость учитывается при подсчёте баллов.

Что хотим сделать дальше

Добавить сравнение ФИО и почты с учётом опечаток. Затем — экран сравнения двух запусков, чтобы при смене порога видеть, какие пары добавились или выпали, а на размеченных данных — сколько связей оказалось верными и сколько ложными.
